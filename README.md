# 工程契約與驗收管理

每個工程依時間分三個階段管理：

1. **技術服務**（委託建築師／技術顧問設計監造）：依工程會「公共工程技術服務契約範本」產生契約 Word 檔；依契約第7、8條自動計算服務實施計畫書、設計成果交付與學校審查期限。
2. **施工**（營造廠）：施工廠商、工程契約金額、開工日、工期、展延 → 自動算出預定竣工日。
3. **竣工驗收至保固**：報竣到保固 33 項檢核，預定竣工日由施工帶入。

委託監造時，監造單位即技術服務廠商（乙方），LINE 通知自動對應。期限計算：工作天不計週六日及「學校設定」中的放假日；「自通知指定之日起」當日算入、「收到後」次日起算；日曆天末日遇放假日順延。
網頁放在 GitHub Pages，資料存在 Google 試算表，同仁不需要 Claude 帳號。

## 部署步驟

### 一、Google 試算表＋Apps Script（後端）

1. 用要存資料的 Google 帳號新建一份試算表，例如命名「技術服務契約產生器資料」。
2. 選「擴充功能 → Apps Script」，刪掉預設程式，貼上 `apps-script/Code.gs` 的全部內容，按儲存。
3. 左側「服務」旁按 **＋** → 選「Google Calendar API」→ 新增（識別碼保持 `Calendar`；不用共用日曆可略過）。
   接著上方函式選單選 `setup`，按「執行」，依提示授權（試算表、雲端硬碟、日曆、寄信、排程）。
   執行記錄會顯示**存取碼**；要改的話到「專案設定 → 指令碼屬性」修改 `ACCESS_CODE`。
4. 右上「部署 → 新增部署作業」，類型選「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**（一定要選這個，網頁才連得到）
   按「部署」，複製網頁應用程式網址（以 `/exec` 結尾）。

### 二、GitHub Pages（網頁）

5. 在 GitHub 新增一個 repository（例如 `tech-contract`）。
6. 「Add file → Upload files」，把 `apps-script` 以外的檔案全部拖上去，按 Commit。
7. 點開 `config.js`，按鉛筆圖示編輯，把第 4 步的網址貼進 `API: ""` 的引號裡，按 Commit。
8. 「Settings → Pages」：Source 選「Deploy from a branch」，Branch 選 `main`、`/ (root)`，按 Save。
   約 1～2 分鐘後網址為 `https://<GitHub帳號>.github.io/tech-contract/`。

### 三、開始使用

9. 打開網址，輸入存取碼（每台電腦只需輸入一次）。
10. 先到「學校設定」確認甲方名稱、放假日、申訴審議委員會、保險與違約金等，按「暫存」。
11. 把網址和存取碼給需要的同仁。

## 日常操作

- **照「下一步」做**：每個工程頁上方紅框顯示現在該做的一件事，按「前往」跳到要填的欄位（下載契約時也會自動切到招標版或簽約版）。工程總表也列出各案的下一步，點該列直接帶到那一格。
- 填完或改完按右上角 **暫存**（或 Ctrl+S）。還沒暫存的修改會先存成這台電腦的草稿，重新開啟會提示還原。
- 兩人同時改同一個工程時，後暫存的人會看到提示，可選「改用對方版本」或「用我的版本覆蓋」。
- 下載 Word 前會自動暫存。
- 試算表的「工程」工作表每列一個工程，可直接備份或檢視；不要手動修改 `data` 欄。

## 服務費參考試算與提醒

- 「計價」區輸入預估建造費用，依《機關委託技術服務廠商評選及計費辦法》附表一（建築物，選第一～四類）或附表二（非建築公共工程）分段累進試算，可一鍵帶入服務費或費率。附表為編列預算之參考，費率仍須簽報核定。
- 服務費達「學校固定設定」中的公告金額（預設 1,500,000 元）時，輸出欄會提醒招標文件須納入《臺北市政府委託技術服務履約績效管理要點》。

## 竣工驗收檢核與工程總表

- 「工程 → 竣工驗收至保固」：每個工程一份，依「B.3完工驗收階段」資料夾整理的 6 階段 33 項。各項附資料夾範本檔連結（需有該雲端資料夾的檢視權限）。
- **不必逐項勾**：依序填 10 個關鍵日期（收受竣工報告日、會同查證日、收受竣工文件日、初驗合格日、驗收合格日、結算驗收證明書核定日、尾款付款日、保固年數、保固期滿會勘日、保證金發還日），之前的例行項目自動標為完成（狀態顯示「自動：已完成」，日期以推定日帶入）；應完成日自動計算，逾期標紅。
- **依金額自動排除**：「施工」頁填工程預算金額後，免初驗的工程自動排除初驗項目，未達查核金額的自動排除報上級機關監辦項目。門檻在「學校設定」（預設：預算逾 2,000 萬元須初驗；5,000 萬元以上為查核金額）。
- **例外才手動**：驗收不合格或保固期間發現瑕疵，按「發生例外時」的按鈕，相關項目改為辦理中並排到下一步最前面；任何一項都可手動改狀態，改回「自動」即恢復判斷。付款後的監造報告書核定、工程決算書這類沒有日期可推定的項目，下一步會提醒手動改為已完成。
- 工程發包（填決標日或開工日）後，技術服務履約頁的設計階段期程自動視為完成。
- LINE 通知：需要廠商或監造配合的項目有「LINE 傳送」（手機直接開 LINE 選聊天室）與「複製訊息」按鈕，訊息自動帶入學校、工程、事項、期限與表單名稱；按過會記錄「已通知」日期。施工廠商稱呼在「施工」頁填寫，技術服務廠商稱呼在「技術服務履約」頁填寫。
- 「工程總表」上方「近期該通知」列出所有工程 7 日內到期或已逾期、3 日內尚未通知的事項。
- 「工程總表」：所有工程的目前階段、下一步、最近到期事項與逾期項數，逾期的排最前面。
- 中途才建檔的工程（契約早已簽好）：直接到「施工」頁填決標日或開工日，下一步就會略過技術服務契約的步驟。

## 同仁共用與通知（學校設定 → 同仁共用與通知）

一份名單管三件事，每位同仁可個別勾選：

| 勾選 | 對方得到 |
|---|---|
| 日曆 | 共用的 Google 日曆「甲方名稱＋工程期限」：各工程未完成事項的期限，每次暫存自動同步，完成的事項會移除 |
| 資料夾 | 雲端硬碟「甲方名稱＋工程文件」資料夾的檢視權限，可開啟網站上傳的檔案 |
| 週報 | 每週一早上 7～8 點收到期限週報：已逾期、7 日內、8～30 日內到期的事項（沒有到期事項的週不寄） |

- 日曆與資料夾需要 Google 帳號（學校帳號或 Gmail 都可以），加入後對方會收到 Google 的共用通知信；週報任何 Email 都能收。
- 先按「建立」日曆與資料夾、按「開啟」週報，再加入同仁；之後勾選或取消立即生效。「現在寄一封測試信」可先確認內容。
- 日曆活動與週報裡都有網站連結，點了直接開到該工程的下一步。建議同仁把這個日曆的通知設成「全天活動前一天」提醒。
- 沒有 Google 帳號，或用 iPhone、Outlook 行事曆的人：用部署帳號登入 Google 日曆 →「設定和共用 → 整合日曆」，複製「iCal 格式的私人網址」給對方訂閱。只能查看、更新較慢；網址等同密碼，外流時在同一處按「重設」。
- 部署帳號若是學校網域帳號，網域管理員可能限制對校外帳號共用；加不進去時網站會顯示原因。
- 不要直接在日曆上改活動，下次同步會被覆蓋。試算表的「期限」「同仁」工作表由網站維護，請勿手動修改。

## 工程文件、缺件檢查

- 技術服務履約、竣工驗收清單的每一項都有「上傳檔案」：檔案存到該工程的雲端資料夾（依技術服務、施工、報竣、竣工文件審查、初驗與驗收、驗收合格與結算、付款與決算、保固分好子資料夾），檔名前會加上文件名稱，網站上顯示 📎 連結。單檔上限 20MB，更大的（例如竣工圖）請按工程頁上方「📁 雲端資料夾」直接放入。
- 「竣工驗收至保固」的「缺件檢查」：列出已完成或辦理中、但還沒上傳應留存文件的項目，可直接上傳，或「複製缺件清單」／「LINE 傳送」給監造、廠商補件。

## 公文簽稿（工程 → 公文簽稿）

依工程資料自動帶入 5 種常用草稿：簽請辦理驗收（簽）、驗收通知（函）、驗收不合格限期改正（函）、驗收後付款（簽）、保固保證金發還（簽）。

- 依預算金額自動寫「初驗」或「驗收」，達查核金額會加上報請上級機關監辦。
- 「○○」是還缺的資料，在左側補填（存在該工程）；付款簽呈填結算金額與已付金額後自動算尾款。
- 可分別複製主旨、說明貼到公文系統，或下載 Word。竣工驗收清單中對應的項目也有「產生簽稿」按鈕。
- 簽的承辦單位在「學校設定 → 承辦單位」；施工契約的工程名稱可在「施工」頁填寫（留空時由技術服務案名推得）。內容為草稿，請依學校公文規定修改後再陳核。

## 修改紀錄、匯出報表

- 每次暫存會記錄誰改了哪個欄位（原值 → 新值），工程頁上方「🕘 修改紀錄」可查看；完整紀錄在試算表「修改紀錄」工作表。請每位同仁在左下填「你的名字」。
- 「工程總表 → 匯出 Excel 報表」：工程總表（階段、完成率、下一步、金額、主要日期）與期限明細（所有未完成事項依期限排序，逾期標紅）兩個工作表。

## 範本改版

到「範本管理」上傳新版 .docx。網站會列出：與目前版本完全相同、文字有改（自動對應）、新增、刪除的填寫點，確認後按「儲存並啟用」。
上傳的範本存在 Google 雲端硬碟的「技術服務契約產生器_範本檔」資料夾，舊版可隨時切回。
若新版改了「未載明者為○○」的預設值（例如減價收受違約金 20% 改 10%），而學校設定還是舊數字，比對結果最上方會出現橘色警告，可逐項或「全部改成新預設值」；改完記得按「暫存」。若當下沒處理，啟用後頁面上方也會持續提醒。
若比對結果出現紅字「自動填」的項目在新版找不到，表示表單有一項設定對不上新條文，請把比對清單（「複製比對清單」）交給 Claude 調整。

## 之後修改 Apps Script 程式／更新版本

1. Apps Script 編輯器：用新版 `apps-script/Code.gs` 全部取代舊程式，按儲存。
2. 若還沒加：左側「服務」＋「Google Calendar API」。
3. 函式選 `setup` →「執行」一次，依提示授權新增的權限（已有的資料、存取碼不會變）。
4. 「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本：新版本 → 部署」，網址不會變。
5. GitHub：上傳新版檔案覆蓋舊檔，**不要覆蓋 `config.js`**（裡面是你的 Apps Script 網址）。

## 更新網頁時

- `index.html` 裡每個 `.js`、`.json` 後面都有 `?v=日期`，`sw.js` 第一行有 `VERSION`。上傳新版檔案時，把這兩處改成同一個新日期，同仁打開網站或手機 App 就會拿到新版，不會用到舊檔。
- 存取碼連續輸錯 30 次（15 分鐘內），後端會暫停 15 分鐘，防止被猜中。

## 手機 App

網站可以直接加到手機主畫面，用起來跟 App 一樣（全螢幕、有圖示），資料和電腦版是同一份 Google 試算表。

- **iPhone**：用 Safari 打開網址 → 下方「分享」→「加入主畫面」。
- **Android**：用 Chrome 打開網址 → 右上「⋮」→「安裝應用程式」（或「加到主畫面」）。

手機和電腦可以同時使用：回到畫面時、以及每 2 分鐘，會自動取得其他裝置暫存的最新資料（有還沒暫存的修改時不會覆蓋）。兩邊同時改同一個工程，後暫存的人會看到提示，可選用哪一版。
